# Pixel 10 収益カレンダーウィジェット — 開発引き継ぎ（監査・公開前）

## 範囲
- 新規の **別 AppWidgetProvider** `CalendarWidget` を追加。既存の3段ゲージ（`RevenueWidget`、レイアウト、色、目標線）は変更しない。
- ヘッダー左：表示（3種類／合計／Coupon／TikTok Lite）、中央：年月選択、右：月計（合計→Coupon→TikTok Lite）。
- 日別は日付と3金額。値を取得できない場合 **「—」**。0円と不明を混同しない。
- 端末内状態はウィジェットIDごと。年月・表示モードのみ保存。日付はJST基準。
- 5×5ホーム配置を念頭に初期サイズ5×5セルへ調整。6週・文字切れ・タップ領域の**実機受入未確認**。Pixel Launcherの実グリッド/壁紙とスタイル設定に依存。

## 確認した既存取得経路
1. **Coupon**: 当選管理のVault D1 `items.received_at` + `item_campaign_assignments` + `ledger_products.unit_price` から、`getRevenueSummary()` は **当日だけ** を計算できる。中央Ledger `product_monthly_revenue` は月単位の集約のみ。
2. **TikTok Lite**: ARUNO ASSISTはCSV **原本を端末ローカル** `files/pay-sync/YYYY-MM.csv` に保存する。THE FOOL QUESTネイティブは従来CSV月合計＋手動追加の日付を保存。新CSV取込処理は日付列を解釈できた場合だけ `nativeRevenueV1.months[YYYY-MM].csvDaily` に合計と一致する日別内訳を保存する。
3. 公開のLedger `/api/v1/revenue/monthly?month=YYYY-MM` は月合計のみ。中央LedgerにTikTok Lite日別・CSV原本が同期されている証跡はない。
4. 本番D1への読み取り権限がこの作業ではないため、実レコード件数・日別データの実保存有無は未確認。

## 2026-11-04：日別6桁表示への追加改修
- カレンダーの日別「合計／C／T」は **0～999,999円を常に6桁まで省略なし・カンマなし** で表示。例：999999、C 999999、T 999999。金額区分は行順と色、C/T記号で識別。
- 日別7桁以上だけ万・億へ切替。値を四捨五入する時は「≈」を付ける。月計は円記号＋3桁区切りの正確な金額を2行ヘッダーに表示。
- 各日の金額欄は等幅フォント7.5sp。5列全幅かつ高さ5セルの配置を想定し、最小横幅320dp・高さ340dpに引き上げ。**Pixel 10実機で6週×3行が欠けないか、フォント倍率を含めWorkで要検証**。
- Android非依存の金額整形用単体試験を追加。実行成否は実際の試験証拠と区別する。
- 前回レビューから残っていたCSVデコード分岐を修正。UTF-8として正しくデコードできたCSVの構文エラーをMS932で再解釈して受理しない。

## Museレビュー照合・事前改修（2026-11-04）

- Muse独立レビューでの「BOM付きCSVの先頭日付認識不具合」は、現在のソース `RevenueManager.parseCsv` の `if(i==0&&ch=='\\uFEFF')continue;` と矛盾。**既存コードですでに先頭BOMを除去**している。BOM付きCSVの回帰計測テストを追加した（Android計測テストはWorkで実行）。
- Vault `src/ledger.js` に `export async function getRevenueSummary` が実在。既存の日付集計は当日限定で、任意の過去月の全日分Readerではない。この点はMuseの「未確認」を実コードで解消。
- 初期表示はJST当月を自動追随。過去月を明示選択した場合だけ固定。年月ダイアログに「今月に戻す（自動）」を追加し、以後の月替わりは自動追随する。
- カレンダー選択ダイアログは透過Activity＋明示AlertDialogテーマで描画し、背後の空白画面を避ける候補とした（実機要検証）。
- `minHeight` と `minResizeHeight` を360dpへ統一。6週×3行・最大フォントの文字切れはWorkのPixel 10実機で検証する。
- 元のサーバー/APIや3ゲージの表示ロジックを変更せず、データ未取得は「—」のまま。本番・署名・CI・実機受入は引き続き未実施。

- 追加検出：日付列のあるCSVで日付が壊れている場合、従来のドラフトでは月計のみとして当月に保存し得た。誤計上防止のため**不正日付の行が見つかったらCSV全体を拒否**し、既存月計/日別を保持する。Android計測回帰テストを追加（未実行）。

## 実運用フロー訂正（ユーザー確認・2026-11-04）
- **ARUNO ASSISTは使わない。** THE FOOL QUESTネイティブアプリの「えらべるPayのポイント履歴をChromeで開く」→ChromeでCSVダウンロード→THE FOOL QUESTの「CSVを取り込む」からファイル選択、という既存の運用を維持する。
- 実コード `ManagementActivity.showHome()` にChrome起動とCSV取込の2ボタンが存在。カレンダー向けTikTok日別集計は**このCSV取込経路内で完結**させる。ASSISTの `paySync` 拡張は今回の要件から除外し、他アプリ改修・追加権限を要求しない。
- 現在のドラフトでは日付付きCSVを取込時に日別集計・保存する処理がある。実CSV原本で日付・BOM・文字コード・月次照合をWorkで確認する。既存の月間収益・手動追加を維持し、同じCSVの再取込で二重加算しない。
- クーポン日別Readerは引き続き未実装・統括確認が必要。Workの監査・本番公開範囲は変更しない。
