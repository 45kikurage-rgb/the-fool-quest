# THE FOOL QUEST Android収益ウィジェット

独立APK `com.aruno.foolquest.widget`。Android 8.0以上。公開済み正式版は v0.1.10 / versionCode 11。既存のTHE FOOL QUEST、ARUNOMATIC、Vault、Ledgerへの書き込みを行いません。

## 現在のデータ責任

- Coupon：既存Ledger `GET /api/v1/revenue/monthly?month=YYYY-MM`、`coupon_revenue`。認証情報を含まない既存公開Readerを再利用。
- TikTok：THE FOOL QUESTのブラウザ内の月別CSV金額＋当月の手動チャージ。`widget-export.html` が保存済み値を読み、ユーザーの確認後、アプリの表示キャッシュへ渡します。
- 目標：同じブラウザの `foolQuestGoalAmounts`。未設定時は既存サイトと同じTotal 1,000,000円、TikTok/Coupon各500,000円。
- Total：同一月のTikTok＋Coupon。未連携のTikTokを0円とは扱いません。

**制限：** 現行サイトにはTikTok・目標を取得するAPIがありません。30分・タップ更新はCouponのみ。TikTokと目標はサイトで変更後に再連携が必要です。完全自動同期を実装済みとは扱いません。新DB、共有API契約、認証は追加していません。

## 表示と操作

5×2初期サイズ、縦3行、現在額・スラッシュ・目標額を個別の固定欄にし、足りない桁は空白の幅を保持。単幅数字、7桁金額2個・小数2桁パーセント。ゲージは100%で上限、数値は実際の割合。文字・余白が収まらない設定は描画時に縮小し、設定画面で警告。

タップで設定画面と同じRevenueUpdateから取得開始。更新用Activityは取得開始後に専用タスクをホームの背面へ移し、完全透明で、前面のフロートを表示せず、ウィジェット内の小さな「更新中」だけを表示します。終了後は更新用Activityを閉じます。JobSchedulerで30分間隔の取得（省電力時は遅延可）。重複要求はプロセス内で同じ通信に合流し、全呼び出し元を実際の完了後に通知。通信失敗・不正応答時は正常値を保持。再起動時は保存値を先に描画。長押しのサイズ変更・設定はランチャー依存。設定はアプリからも可能。表示設定は全インスタンス共通。

## 過去の変更：v0.1.7：通信遅延への対応・安全な失敗理由

接続と読み込みの待ち時間をそれぞれ2.5秒から10秒へ変更。本文は10秒の時間検査と32KBの上限を維持し、リダイレクトは許可しません。初回配置とタップ更新は、同じJobServiceの単発ジョブへ要求してBroadcastReceiverをすぐ返します。受信処理の短い実行期限内に長い通信を抱え込まないための変更です。新規常駐サービス・独自WakeLock・新規権限は追加しません。標準JobSchedulerの実行時刻はOS制御の影響を受けます。

未接続、時間切れ、名前解決、TLS、HTTPステータス、不正応答などを制御された理由コードへ分類。現在の失敗理由はウィジェットの小さい状態行へ表示し、直近の失敗理由と日時はアプリの設定画面のみへ表示。例外の生メッセージ、URL、応答本文、認証情報は保存しません。成功すると現在のエラーは消え、直近失敗の履歴は端末内に残るため復旧後も確認できます。既存の正常収益値と取得日時は失敗時に保持します。

ユーザーの一時失敗は再タップで復旧したとの報告。開発環境からの実API接続はHTTP200・正常契約・43bytes、TLS接続を含む約7.9秒でした。旧版の2.5秒設定は原因候補ですが、端末の失敗理由を記録していなかったため今回の原因そのものは確定できません。
