# Aruno-Result 自動バックアップ・復旧

## 最初の1回だけ

1. 今使っている版の「バックアップ・復元」から、現在の収益履歴をJSONで書き出します。
2. Aruno-Resultを削除せず、新しいAPKを上書きインストールします。
3. 管理画面→「バックアップ・復元」→「自動バックアップ・復旧を開く」。
4. 「保存先を選択・権限を再設定」を押し、端末内のDocuments等に作った `Aruno-Result` 専用フォルダーを選びます。
5. 最終成功日時と正常性を確認します。以後の登録・変更では手動保存は不要です。

保存先は、この初回操作で選んだフォルダーです。例：内部ストレージ/Documents/Aruno-Result。アプリ内専用領域やAndroid/dataではありません。JSONはFilesアプリから取り出せます。クラウドのフォルダーは今回の自動保存先に選べません。

## 保存する内容とタイミング

CSVの月別・日別データ、TikTok手動収益、TikTok/Coupon損失、取得済みCoupon履歴、目標、ゲージの表示設定、カレンダーのウィジェット別設定を、変更確定時に保存します。通常データの確定後、バックアップも再読込・SHA-256照合します。連続操作は確定した各変更を順番に保存し、保存できない場合は画面・トーストで通知します。

- 通常の変更：直近10世代
- 日別の正常な退避：通常変更とは別に10世代
- 更新・復旧前の保全：さらに別に10世代

ファイル名は `aruno-result-change-...json`（変更）、`aruno-result-daily-...json`（日別）、`aruno-result-safety-...json`（保全）です。`.pending` は保存途中のため復旧対象にしません。壊れたJSON・空データで、既存の正常なファイルを上書きしません。

## 復旧するとき

1. 同じ「自動バックアップ・復旧」画面を開きます。
2. 「保存済みバックアップの一覧」または「JSONファイルを選んで復旧」から選びます。
3. 日時・件数・目標・正常性を確認し、「確認して復旧する」を押します。
4. 現状の保全が完了してから、収益・損失・目標・表示設定を復旧します。復旧後の金額・設定を確認してください。

確認後に別の変更が入った場合は、復旧を止めて再確認します。勝手に過去データへ戻すことはありません。Couponは表示用キャッシュとして扱い、バックアップ復旧からサーバーのデータを書き換えません。現在の同じ月の取得値を維持し、バックアップだけにある過去月を補います。

## 権限・初期化・ウィジェットについて

保存権限を失った場合は、フォルダーを再選択して再試行します。保存待ちの確定変更は、アプリ内の退避領域から再送します。未保存分が32MiBを超えた場合は、取りこぼさないため新しい保護対象の保存をエラーにして、保存先の確認を促します。

アプリのデータを初期化しても、選択フォルダー内のファイル自体は残ります。ただし、保存先の再選択が必要です。認証キー・パスワードはバックアップに含めないため、日別連携キーも再入力してください。端末の初期化やフォルダー自体の削除ではファイルも失われるため、必要に応じてFilesから端末外へコピーしてください。

ホームの配置はAndroid/ランチャーが管理します。ウィジェット自体が消えた場合は再配置してください。同じウィジェットIDの表示設定は復旧できますが、新しいIDへは月・表示種類を選び直す必要があります。

11月7日に失われた過去データの原因解明や復旧が完了したという意味ではありません。保存されていなかったデータを、この機能だけで復元することはできません。Pixel 10実機の上書き・見た目・実データ保持は、ソフトウェア試験とは別に確認します。
