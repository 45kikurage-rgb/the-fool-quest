## Storage and durability

User selects a dedicated local device folder once through ACTION_OPEN_DOCUMENT_TREE (e.g. Documents/Aruno-Result). Only Android's external-storage document provider is accepted, so this is a local device backup, not a cloud provider. Android storage-root, Download-root and Android/data restrictions are respected. Persisted read/write URI grant survives normal update/reboot; after clearing app data the files survive but the folder must be selected again. Moving/deleting the folder or revoking access produces a persistent error and toast; retry/reselection replays confirmed pending changes.

Every existing preference write uses a serialized transaction wrapper. Recognized income/settings are type/schema validated, staged with AtomicFile before normal disk commit, reread and compared, then appended to an independent journal. All apply calls at this boundary use synchronous disk commits. A durable outbox feeds a single background writer; edits are not debounced away. Startup promotes a crash-interrupted transaction only when its full typed snapshot matches the persisted normal state. Uncertain records are quarantined, not auto-restored. An outbox exceeding32MiB blocks new protected mutations with an explicit error rather than silently discarding pending changes. No foreground service or continuous polling is added.

External documents are unique immutable files: .pending write→flush/fsync→full readback→rename .json→full readback/SHA validation. Existing normal files are never overwritten. Interrupted .pending files are excluded from normal recovery. Only validated committed generations count toward retention: last10 changes, first nonempty good snapshot of each of last10 days, and10 startup/version-change/pre-restore safety snapshots. The earliest daily anchor does not turn over on frequent edits. Pruning follows successful new-file validation. Corrupt files are retained and counted separately. Local confirmed files are not pruned until external copy acknowledgment; older exported files follow the same three10-generation pools.

All current revenue mutations reload the latest confirmed native history under the same lock, preventing stale Activity/model instances from dropping another confirmed mutation. Removal of native history or transition from known nonempty records to completely empty data is blocked. Network/authorization/reconciliation failure no longer deletes the last-good daily Coupon snapshot. No automatic recovery or server write is performed.

## Recovery

Management→Backup/restore→Automatic backup/recovery. Shows destination, latest external success timestamp, record count and integrity/error state. Validated external/local generations can be selected, or a JSON selected directly. Preview shows months/manual/loss counts, goals and checksum. A user's explicit confirmation is required. The current typed state must still match the preview's fingerprint; otherwise re-preview is required. Current data is independently written/read-verified in the selected local folder before any replacement. Local data and display settings are restored together with typed numeric values; current acquired Coupon cache and current authorization remain intact. Missing acquired Coupon cache can use the backed-up read-only projection; no data is sent to the server.

No authentication token/password is included. Clearing app data invalidates AndroidKeyStore credentials; the read-only daily key must be reentered. Launcher placement cannot be recreated by a data JSON; if Android removes widgets, re-add them. Per-widget preferences are retained with their IDs; existing host IDs retain their settings. Different/new IDs need manual selection in the UI. These OS constraints are not claimed as automatically recovered.
