# Code44 checkpoint — month-end forecast title reserve fit

Version 0.1.43 / code44; PR #64; public code43 unchanged until merge. User instructed on 2026-11-13 to re-check the cause from another angle and, if sound, proceed as code44 through production publication (all GitHub operations for this matter pre-approved, no per-step confirmation).

## Origin
Pixel 10 physical check of code43 (2026-11-13, user screenshot): the calendar month-end forecast title still rendered only 「月末予」 — the fourth glyph 「想」 was entirely missing, exactly as in code42. The code43 −3 size cut therefore did not change the rendered title on the device, although the emulator gate showed four glyphs. The remaining code42 checklist items (in-place update retention, settings persistence, offline, restore) are still unreported.

## Root cause (measured, reproduced in the gate)
1. The title fit normalizes the rendered width to the amount budget while it binds: `setTextScaleX(amountWidth / titleWidth)` with the title laid out at the same budget. Rendered width is therefore size-independent under the fit, so the code43 −3 cut (size 17.8→14.8) only moved scaleX (0.765→0.92) and left the drawn width at ~51.7dp. The header keeps a 16dp reserve and the daily totals keep 1px; the title alone had only ~0.6dp of margin.
2. On the device, pixel-snapped advances overshoot the budget by ~1–3px in total (screenshot: glyph pitch 13.53dp vs theoretical 13.18dp), the single-line title (maxLines=1, no ellipsize) wraps the last glyph to a second, invisible line.
3. The instrumentation never rendered the calendar tall enough for the fit to bind (236dp loops shrink dateSize to ~6dp; the 440dp interaction geometry leaves ~3.2dp of slack), so the gate could not see the defect. Font metrics measured from the shipped font: kanji advance 0.95em (「月末予想」 = 380 @100), digits 0.609em; device dateSize ≈ 17.8dp back-computed from the screenshot.
Fix rule (independently re-reviewed before implementation): title size = min(dateSize − 3, fit size for budget − 4dp reserve); the backstop scaleX is computed against the same reserved budget. The min() keeps every existing fixture geometry on the old value, so no existing assertion changes meaning. Expected device title ≈ 12.6–12.8dp (about −15% vs code43), matching the approved mockup direction.
